## 1. Overview & Objectives

Based on [docs/prompt.md](file:///run/media/iamblitz/CODES/SecurePM/docs/prompt.md) (Prompt 3) and user decisions:
A project can be managed using either an **Agile** (concurrent/independent) or a **Plan-Driven** (sequential/phase-gated) approach through sub-project level dependencies.

1. **Dependency Types**:
   - `NO_DEPENDENCY` (Independent / Parallel): Operates standalone without upstream blockers. Can still serve as an upstream prerequisite for other sub-projects.
   - `START_AFTER` (Sequential / Dependent): Requires one or multiple prerequisite sub-projects under the same parent to be formally finished (`completed == true`) first.
2. **First Sub-Project Exception**:
   - The very first sub-project created within a project cannot have dependencies; dependency inputs are hidden/disabled by default with an explanatory note.
3. **Sub-Project Creation UI & Flow**:
   - When creating subsequent sub-projects:
     - **Dependency Type Dropdown**: `"No Dependency"` vs `"Start After"`.
     - **Target Sub-Project Selector**:
       - If `"No Dependency"`: target selector is disabled and cleared.
       - If `"Start After"`: target selector becomes active, allowing multi-selection (checkboxes) of existing sibling sub-projects.
4. **Execution Rules & Status Freezing (Blocked State)**:
   - When a sub-project has `START_AFTER` dependencies and at least one prerequisite is incomplete:
     - **Task Creation**: Strictly blocked (backend returns 400 Bad Request; UI hides/disables "+ New Task" button and Kanban "+ Add task" shortcuts).
     - **Task Status Changes**: Disabled and blocked (dragging tasks across Kanban columns and updating status in task form/modal are blocked).
     - **Sub-Project Completion**: Marking the dependent sub-project as completed is strictly blocked until all prerequisites are completed.
     - **Permitted Actions**: Assigning/inviting team members, viewing/downloading files, direct library uploads, and file forwarding remain active.
5. **Reopening & Pipeline Integrity**:
   - If an upstream prerequisite sub-project is reopened, downstream sub-projects that depend on it automatically re-enter the blocked state dynamically.
6. **Editing / Removing Dependencies**:
   - Visible to all sub-project members in Sub-Project Settings.
   - **Editing or removing dependencies is strictly restricted to the Main Project Creator and System Admin**.

## 2. Technical Scope & Architecture

### 2.1 Database Schema (Flyway Migration `V12__subproject_dependencies.sql`)

1. Add `dependency_type` to `projects` table:
   ```sql
   ALTER TABLE projects ADD COLUMN dependency_type VARCHAR(32) NOT NULL DEFAULT 'NO_DEPENDENCY';
   ```
2. Create `subproject_dependencies` join table:
   ```sql
   CREATE TABLE subproject_dependencies (
       id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
       subproject_id BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
       prerequisite_id BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
       created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
       CONSTRAINT uq_subproject_prerequisite UNIQUE(subproject_id, prerequisite_id),
       CONSTRAINT chk_no_self_dependency CHECK (subproject_id != prerequisite_id)
   );

   CREATE INDEX idx_subproject_deps_sub ON subproject_dependencies(subproject_id);
   CREATE INDEX idx_subproject_deps_prereq ON subproject_dependencies(prerequisite_id);
   ```

### 2.2 Backend Architecture

1. **Entity & DTO Updates**:
   - `Project.java`:
     - `@Column(name = "dependency_type", nullable = false) public String dependencyType = "NO_DEPENDENCY";`
   - `SubprojectDependency.java` (New PanacheEntity):
     - `subprojectId` (Long), `prerequisiteId` (Long), `createdAt` (LocalDateTime).
   - `CreateProjectRequest.java` & `UpdateProjectRequest.java`:
     - `public String dependencyType;`
     - `public List<Long> prerequisiteIds;`
   - `ProjectDTO.java`:
     - `public String dependencyType;`
     - `public List<Long> prerequisiteIds;`
     - `public List<String> prerequisiteNames;`
     - `public boolean isBlocked;`
     - `public List<String> blockingPrerequisiteNames;`

2. **Service Layer (`ProjectService.java`)**:
   - `createProject`:
     - Validate that if `parentProjectId == null`, `dependencyType` is ignored / set to `NO_DEPENDENCY`.
     - Count existing sub-projects under `parentProjectId`: if 0, enforce `dependencyType = NO_DEPENDENCY` and clear prerequisites.
     - If `START_AFTER`: validate all `prerequisiteIds` exist, are child sub-projects of the same parent, and are not self-referential.
     - Persist `subproject_dependencies` records.
   - `updateProject`:
     - If `dto.dependencyType != null` or `dto.prerequisiteIds != null`:
       - Verify caller is Main Project Creator (`parentProject.createdBy`) or `ADMIN`. Sub-project lead cannot modify dependencies.
       - Update `dependency_type` and replace `subproject_dependencies` records.
   - `isSubprojectBlocked(Long projectId)`:
     - Check if `dependencyType == "START_AFTER"`.
     - Query incomplete prerequisites (`completed == false OR archived == true`).
     - Returns boolean and populates blocking names.
   - `completeProject`:
     - Add gate: if `project.isSubproject && isSubprojectBlocked(project.id)`, throw `IllegalStateException("Cannot complete sub-project: Prerequisite sub-projects have not been completed yet.")`.

3. **Task Gating (`TaskService.java`)**:
   - `createTask`:
     - If `projectService.isSubprojectBlocked(projectId)`, throw `IllegalStateException("Cannot create tasks: Prerequisite sub-projects have not been completed yet.")`.
   - `updateTask`:
     - If `dto.status != null && !task.status.name().equals(dto.status)`:
       - If `projectService.isSubprojectBlocked(projectId)`, throw `IllegalStateException("Cannot change task status: Prerequisite sub-projects have not been completed yet.")`.
   - `moveTask`:
     - If `projectService.isSubprojectBlocked(projectId)`, throw `IllegalStateException("Cannot move tasks: Prerequisite sub-projects have not been completed yet.")`.

4. **REST Endpoints (`ProjectResource.java` & `TaskResource.java`)**:
   - Ensure 400 Bad Request is returned for dependency blocking exceptions.

### 2.3 Frontend Architecture

1. **Type Definitions (`types/project.ts`)**:
   - Add `dependencyType`, `prerequisiteIds`, `prerequisiteNames`, `isBlocked`, `blockingPrerequisiteNames` to `Project`.
   - Add `dependencyType`, `prerequisiteIds` to `CreateProjectRequest` and `UpdateProjectRequest`.

2. **Sub-Project Creation Flow (`CreateProjectModal.tsx`)**:
   - When `parentProject` is set, fetch existing sub-projects: `projectsApi.fetchSubprojects(parentProject.id)`.
   - If `existingSubprojects.length === 0`:
     - Display informational banner: *"First sub-project runs independently (No Dependency)."*
   - If `existingSubprojects.length > 0`:
     - Render **Dependency Type Dropdown**: `No Dependency (Parallel)` vs `Start After (Sequential)`.
     - When `Start After` is selected: render multi-select checklist of existing sub-projects with completed status indicators.

3. **Sub-Project Settings Page (`ProjectSettingsPage.tsx`)**:
   - Add **"Sub-project Dependencies"** card for sub-projects:
     - Shows current dependency type and prerequisite list with completion status.
     - If user is Main Project Creator or Admin: allows editing dependency type and prerequisites, with "Save Dependencies" button and "Remove All Dependencies" option.
     - If user is Sub-project Lead or Member: displays read-only view with note: *"Only Main Project Creator or Admin can modify dependencies."*

4. **Task Board & List Gating (`ProjectPage.tsx`, `KanbanBoard.tsx`, `TaskList.tsx`, `TaskForm.tsx`)**:
   - When `project.isBlocked`:
     - Display a prominent amber warning banner at top of project page:
       `"⚠️ Prerequisite Milestone Pending: Task creation and task status changes are locked until prerequisite sub-projects ([Names]) are marked as Completed."`
     - Disable "+ New Task" button with tooltip explanation.
     - In `KanbanBoard.tsx`: disable drag-and-drop (`isDragDisabled = isCompleted || isBlocked`), hide "+ Add task" shortcuts on columns.
     - In `TaskForm.tsx`: if `isBlocked`, disable status change dropdown with lock tooltip.
     - In sub-project list card (`ProjectPage.tsx` under parent): display badge:
       - If `NO_DEPENDENCY`: `Independent` (slate chip).
       - If `isBlocked`: `⏳ Blocked by [Names]` (amber chip).
       - If `START_AFTER` and not blocked: `✓ Prerequisites Met` (emerald chip).
